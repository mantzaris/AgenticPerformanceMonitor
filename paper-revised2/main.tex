\author{\authorname{Alexander V. Mantzaris\sup{1} and James H. Korris\sup{2}}
\affiliation{\sup{1}Dr. Yvette Kanouff School of Data, Mathematical, and Statistical Sciences, UCF,\\
4000 University Blvd, Orlando, FL, USA}

\keywords{Analytical Agents, Longitudinal Data, Evidence Provenance, Answer Completeness, Adaptive Dashboards.}
\abstract{A question such as "Has this student's activity changed, and how does it compare with their peers?" often requires a dashboard to bring several kinds of information together. We present an agentic dashboard system that organizes real educational activity and assessment records into views suited to different questions. A language model chooses predefined analyses and selects results. Deterministic tools calculate the quantities, validation links them to supporting records, and presentation templates arrange the selected information. The dashboards highlight personal change, compare peer groups and time periods, distinguish recorded zeros from unavailable observations, and present assessment histories. Users can switch among saved comparisons and inspect the evidence behind displayed values. We evaluate three selection interfaces using Qwen2.5-14B-Instruct on 24 development cases from two Open University course offerings. The interfaces produced \AVisible, \BVisible, and \CVisible\ complete visible answers, respectively, compared with \EnumVisible\ for a deterministic baseline. We also distinguish answers selected by the model from information added automatically by the dashboard software. The saved outputs reveal that correct, traceable values can still refer to the wrong period or leave part of a question unanswered. More explicit analytical labels did not improve the original completeness scores, and some equivalent answer forms still require human review. The contribution combines a working adaptive dashboard system, concrete interface examples, and a comparative evaluation showing how analysis selection, evidence checking, and presentation jointly shape the answers users receive.}

\section{\uppercase{Introduction}}
\label{sec:intro}
\noindent Dashboards can help people understand how their activity changes over time and how it compares with that of others. The most useful view, however, depends on the question. A student asking about recent progress needs a comparison with their own earlier activity. A student asking how they compare with others needs a suitable peer group. If recent observations are unavailable, the dashboard should explain the gap instead of suggesting a trend.
This paper develops an agentic dashboard tool around that idea. Using educational activity and assessment records, the tool presents views for personal change, peer comparisons, limited observations, and assessment history. Each view brings the relevant information into focus. For example, a reference selector lets the user explore saved comparisons, while an observation timeline distinguishes weeks with no recorded activity from periods when the student was not eligible to participate.

The system combines a language model with predefined analysis tools and presentation templates. The model chooses analyses and selects results to answer the question. The tools calculate the values, and the software checks their supporting records before assembling the dashboard. A separate presentation layer arranges the selected information into the different views. This division makes the displayed results traceable while allowing the content to vary across questions.
We examine three ways of providing analytical information to the model. These range from a compact interface to richer descriptions of data availability and comparison scope, followed by explicit labels identifying the measure, periods, and reference group. The same model and calculation tools are used throughout. A deterministic baseline selects the required analyses through predefined rules for the same question families.

The evaluation asks whether clearer analytical descriptions help the model produce more complete answers. It also distinguishes information selected by the model from context added automatically by the dashboard software. Inspecting the saved outputs shows where the system answers the question successfully and where it retrieves correct information but chooses an unsuitable comparison or leaves part of the question unanswered.
The contribution is a working dashboard system, a comparison of its selection interfaces, and concrete examples of its behavior. More explicit labels did not improve the original completeness scores. Some alternative answer forms still require human review. The interface examples illustrate practical adaptation, while the evaluation identifies limitations to address in further development.


\section{\uppercase{Related Work}}
\label{sec:related}
\noindent NL4DV connects natural language queries to data attributes, analytical tasks, and Vega-Lite specifications \cite{nl4dv}. NL4DV-LLM extends this approach with conversational interaction and ambiguity handling \cite{sah2024}.

LIDA combines data summarization, goal exploration, visualization code generation and evaluation, and infographic generation \cite{lida}. Data Formulator~2 supports iterative authoring through graphical and natural language inputs, generated data transformations, and branching histories \cite{dataformulator2}. Our system adopts a narrower division of work. The model selects predefined analyses and results, while calculation tools and presentation templates produce the dashboard.

Vega-Lite expresses visual encodings and interactions through specifications that compile into graphical displays \cite{vegalite}. Draco represents visualization design knowledge through hard and soft constraints \cite{draco}. InsightBench studies agents that formulate questions, perform analyses, and summarize insights using datasets containing planted patterns \cite{insightbench}. Here, the questions are supplied, and the observations come from real educational records. We examine whether the model selects enough information to answer each question.

VisEval further distinguishes executable validity, satisfaction of chart and data requirements, and readability \cite{viseval}. Its acceptance of multiple valid charts is particularly relevant to assessing our dashboards. A requested value may appear in different supported answer forms, so checking one expected representation can miss a valid response. This motivates separate checks of numerical support and answer completeness. Some equivalent forms in our development comparison still require human review.

W3C PROV-DM provides concepts for describing entities, activities, agents, and derivations \cite{prov}. This perspective motivates tracking the source results, model selections, automatically supplied context, and final presentation separately.

\section{\uppercase{Data and Analytical Definitions}}
\label{sec:data}
\noindent We use the Open University Learning Analytics Dataset (OULAD), which links course offerings, registrations, assessments, and virtual learning environment interactions \cite{oulad}. The creator deposited UCI archive is distributed under CC BY~4.0 \cite{ouladDataset}. Our audit counted 28,785 distinct people, 32,593 registrations, 173,912 assessment records, and 10,655,280 interaction rows. We checked duplicate keys and many-to-one joins and aggregated interaction and assessment records before constructing weekly features.

\subsection{Development Population and Time}
We selected AAA\_2013J and BBB\_2013B in alphabetical order, requiring at least 100 development students with eight fully eligible weeks and two dated non-examination assessments by day~83. The offerings contained 254 and 1,269 development registrations, representing 1,523 distinct people. A hash assigned approximately 70\% of people to development and reserved 8,583 people, keeping all registrations for each person together. Reserved observations were not used for case selection, fitting, prompt development, or the present comparison.

Week~$w$ covers days $7w$ through $7w+6$ from the offering's start. Only calendar weeks ending by the cutoff are included. Eligibility starts at registration and ends before the withdrawal day. Future withdrawal is masked, and unknown registration leaves eligibility unknown. These rules reconstruct availability retrospectively and have not been validated as a real-time feed.

\subsection{Recorded Measures and Availability}
For person $i$ in week $w$, recorded clicks per eligible day are $x_{iw}=c_{iw}/d_{iw}$, where $c_{iw}$ counts clicks on $d_{iw}>0$ eligible days. Unknown eligibility or no eligible days makes the rate unavailable; an eligible week without recorded clicks receives zero. Logging completeness remains unknown. Click counts do not measure ability, study time, or learning.

Other weekly measures are days with positive activity, distinct resources, non-banked submissions, and scheduled assessments without a recorded submission. Submissions count in their recorded week within eligibility and the cutoff. The scheduled measure counts dated non-examination assessments due during eligibility without a non-banked submission by that week's end. Unknown exemptions prevent interpreting every missing submission as an unmet obligation. Later submissions do not rewrite earlier status snapshots.

Inputs exclude future activity, final results, and future withdrawal. Scores are withheld because submission dates do not establish grade availability. Banked assessments are excluded because approval timing is unknown. The original calculations retain repeated rows. The audit found 787,170 extra copies of identical rows, and 2,195,960 extra rows sharing the same person, offering, site, and day. These combinations do not necessarily identify individual events. Section~\ref{sec:sensitivity} checks how removing exact duplicates affects the current cases.

\subsection{Personal and Peer Comparisons}
Let $O_i(W)$ contain eligible weeks with recorded values in period $W$. The person's mean is
\begin{equation}
m_i(W)=\frac{1}{|O_i(W)|}\sum_{w\in O_i(W)}x_{iw},
\end{equation}
unavailable when $O_i(W)$ is empty. Weeks receive equal weight, including partial weeks after calculating daily rates; this differs from pooling clicks and eligible days. For earlier period $W_b$ and recent period $W_r$, personal change $\Delta_i=m_i(W_r)-m_i(W_b)$ requires two observed weeks in each period.

For reference group $g$ in period $W_g$, peers with at least one nonmissing week form $P_g$. Their equally weighted mean is $\mu_g(W_g)=|P_g|^{-1}\sum_{j\in P_g}m_j(W_g)$, and the focal difference is $D_{i,g}=m_i(W_r)-\mu_g(W_g)$. Comparisons require 20 peers and two focal weeks; individual means can remain available below these prototype thresholds.

The three reference groups include other development students in the offering, those sharing first-attempt or repeat-attempt status, and offering peers in the earlier period. All task participants are excluded across registrations. Earlier-period comparisons change time and potentially membership; they are not necessarily fairer or causally adjusted. Weekly trajectories always use same-week peers.

We draw 500 seeded bootstrap samples of people, retaining their period means, and use the 2.5th and 97.5th percentiles \cite{efron}. Weekly bands repeat this separately by week. No interval is shown with fewer than two peers. Intervals concern peer means only, not individual predictions, personal change, focal differences, or differences between references.

\section{\uppercase{From Questions to Dashboards}}
\label{sec:system}
\noindent The model receives the person, offering, cutoff, periods, task family, question, and shared feature/reference definitions. Structured requests let it run analytical batches, inspect compact results, and request more information or finish. Evaluation-only requirements remain hidden, and generated analysis code is not executed.

\subsection{Evidence and Answer Validation}
Evidence records connect each result to its feature, units, periods, counts, estimates, support, observation and assessment states, and uncertainty. They also retain source and configuration hashes, random seeds, and execution details. The model receives summaries rather than raw rows, while full evidence remains available for inspection.

Each peer-comparison label identifies the person, offering, cutoff, measure, periods, and peer group. Personal-change labels identify the earlier and recent periods without a peer group. Labels can refer only to returned results. Unknown or ambiguous labels are rejected. For the same person, measure, units, and cutoff, repeated personal summaries can share a label only when their values, periods, counts, and support agree exactly.

Validation checks results against the trusted development data, including summaries, trajectories, counts, intervals, units, groups, periods, and eligibility. Changing values and recomputing their hash cannot bypass these checks. These checks establish consistency with the implementation, while scientific adequacy and answer completeness require separate assessment.

\subsection{Building and Tracing Answers}
Selected peer comparisons become claims and panels; personal results become claims and trajectories. Support rules determine whether wording describes a result or explains insufficient observations. Unknown grades remain unavailable measurements. The compiler, which builds the dashboard, adds required timelines and explanations about available records. It does not add missing peer or personal comparisons. These additions can still answer a requested item, such as grade availability. The saved record distinguishes the model's choices from information added by the software. All numerical calculation and insertion are deterministic.

\subsection{Adaptive Presentation of Saved Answers}
The publication views reorganize saved content after the experiment. They introduce no evidence, corrected omissions, or revised scores. Layout follows content rather than case identifiers. Equivalent personal duplicates may be combined with original multiplicity recorded; distinct peer claims remain available. Evaluation uses complete original dashboards.

Figure~\ref{fig:adaptation} shows personal and limited-observation views. All views retain expandable evidence, zero/unavailable distinctions, and intervals for peer means only. Figure~\ref{fig:reference} switches between saved model-selected comparisons: values, counts, labels, charts, and evidence links update together without recalculation or new analysis.

\section{\uppercase{Experiment}}
\label{sec:experiment}
\noindent Four conditions answer identical questions about 24 additional development participants, four per question family. Earlier development established the backend, policy, compiler, and evaluator; its participants are excluded and its results are not pooled here.

\subsection{Cases and Shared Information}
The six families address personal change alongside peers, named reference groups, observation availability, separate personal/peer insufficiency, assessment means with grade context, and alternative periods. Profiles compare weeks 0--3 with 8--11 at day~83, 0--3 with 4--7 at day~55, 0--1 with 2--3 at day~27, 0--3 with 10--11 at day~83, and 2--5 with 6--9 at day~69. Questions specify measure, periods, and cutoff.

Selection uses administrative eligibility and previous attempt status where relevant, never activity magnitudes or model outcomes. Insufficiency cases require fewer than two recent eligible weeks and at least one earlier week. We choose the unused eligible person with the smallest SHA256(seed, case, person), using seed \texttt{stage6-structural-v1-20260918}. All 57 previous and 24 new task participants are excluded from peer pools across registrations. Separate row-based calculations checked 52 fact records; this is computational checking, not human review.

All conditions share questions, family labels, definitions, and interpretation rules. Tasks, prompts, code, sources, settings, scoring, and order were frozen before inference, without subsequent tuning or reruns to obtain success. Hidden facts support only scoring and diagnosis.

\subsection{Conditions and Ablation}
\textbf{Enumeration} follows rules for public families and references using the shared backend, validator, renderer, and six-call limit. Family labels make it a strong baseline for defined tasks, without implying general language understanding.

\textbf{A, compact} selects answer types and returned identifiers, with the model specifying support and conclusion scope. The existing compiler constructs the dashboard.

\textbf{B, derived metadata} retains these selections but determines support and scope automatically, uses a neutral heading, and supplies a catalogue of returned answers. Comparing B with A therefore tests this combined interface change.

\textbf{C, explicit binding} selects exact analytical labels while retaining B's automatic metadata and identical catalogue. Comparing C with B tests how answers are identified while keeping available information equivalent. None receives hidden scoring requirements or automatically supplied missing comparisons. An agent can still select a valid result that does not answer the question.

\subsection{Model, Budgets and Outcomes}
Agents use Qwen2.5-14B-Instruct \cite{qwenReport,qwenCheckpoint}, revision \texttt{cf98f3b3bbb457ad9e2bb}\allowbreak\texttt{7baf9a0125b6b88caa8}, Transformers 4.55.2, greedy decoding, and BF16 on one RTX~6000 Ada GPU without quantization or offload. Limits are 16,000 input and 1,500 output tokens, six analytical calls, four generations, and one final repair using integrity errors and existing evidence, without completeness feedback. No fallback answers are supplied.

Six A/B/C orderings repeat four times, balancing positions and pair order. Each method answered each of the 24 questions once; enumeration used the host CPU. An accepted output passes format, scope, support, evidence, numerical, and rendering checks. First final validity excludes repairs but allows earlier tool errors. Complete visible answers also meet every scoring requirement set before the experiment. Method-selected completeness counts only answers selected by the agent or baseline rules. Failed cases remain in the totals, and extra panels earn no credit. The prespecified target required 22/24 complete visible answers, no accepted unsupported quantities, and separate personal/peer answers on all four insufficiency cases. Section~\ref{sec:sensitivity} reports additional analyses performed after the original experiment.

\subsection{Accepted and Complete Answers}
All 24 B outputs passed validation, but fewer were scored complete than in A. Final repairs succeeded in one of three attempts for A, two of two for B, and zero of three for C. No agent met the combined target. Information added by the dashboard software completed three A cases, one B case, and four C cases. It added no missing peer or personal comparisons.



\subsection{Why Some Answers Were Incomplete}
Inspection of saved results found enough evidence to answer all 24 questions in A and B, and 21 in C. In case~15, A nevertheless selected peer comparisons for weeks~0--3 when asked about weeks~10--11. Returned recent evidence supported a separate personal-insufficiency answer, but its peer answer was omitted. The earlier comparison was correct but did not answer the recent-period question.
In C18--20, invalid requests returned no evidence, so the final answers referred to results that had not been returned. These failures occurred before an answer catalogue was returned. None of the 168 model responses reached the output limit. All 91 accepted dashboards passed the numerical checks, although some left part of the question unanswered.

\subsection{Answers the Scoring Rule Missed}
\label{sec:caveat}
In B17--20, the requested recent assessment means appear in personal-change statements. The scoring rule looks for these means in a comparison statement or chart and misses them in this form. If these four cases were counted as complete, B would rise from 15/24 to 19/24. Its score based only on model selections would remain 14/24 because the software supplied the grade-availability explanation. We retain the original scores and report this alternative separately.

C21/C23 show earlier and recent means in peer comparisons without explicitly stating personal change. Whether this answers the question also needs review. These cases have not yet been assessed by two independent human reviewers. The alternative count above does not replace that review.

\subsection{Additional Checks}
\label{sec:sensitivity}
We compared each pair of methods on the same 24 people using two-sided exact McNemar tests, with Holm adjustment for the six comparisons. A completed six more answers than B or C, but these differences were not statistically significant (adjusted $p=0.2813$ each; B versus C, $p=1$). Enumeration completed three more than A ($p=0.5000$) and nine more than B or C ($p=0.0234$ each). Counting B17--20 as complete reduces its gap from enumeration to five cases ($p=0.3125$). These tests were added after the experiment and assume independent cases. The selected students share courses and peer groups, so the results need confirmation on new cases. A nonsignificant result does not show that methods are equivalent.

We also repeated the calculations after removing exact duplicate rows, using the same students, periods, and peer groups. All 29 supported click-rate comparisons and 13 personal changes kept their direction. The median and largest changes in peer differences were 0.167 and 0.324 clicks per eligible day; the largest change in personal differences was 1.393. Assessment summaries, support decisions, and all eight conclusions about changes in comparison direction stayed the same. Thus repeated rows affect magnitudes even where directions persist. Equal rows may represent real events, so removal is an alternative treatment, not a correction. We did not rerun agents or recalculate intervals; completeness scores remain unchanged.

Across 24 cases, enumeration took 35.40~s, compared with 484.64, 504.21, and 536.32~s for A, B, and C. These totals include failed runs and repairs but exclude shared model loading.


\section{\uppercase{Discussion and Limitations}}
\label{sec:discussion}
\subsection{When an Agent Might Help}
Enumeration answered all questions and was cheaper. For this small set of predefined tasks, the study shows no advantage in completeness or running time. An agent might help when a question is ambiguous, needs clarification, or combines analyses not covered by existing rules. We did not test those situations. A useful next comparison would give both approaches the same opportunity to ask clarifying questions and the same analysis budget.

\subsection{What the Figures Show}
In Figure~\ref{fig:reference}, the person's rate remains 3.50 clicks per eligible day while recent and earlier peer means are 3.46 and 6.98. The corresponding differences are +0.04 and $-3.48$, calculated before rounding. Displaying the periods and membership counts makes the reference choice inspectable without suggesting that one group is inherently preferable or that the difference is causal.

These figures show how recorded activity can be presented and compared. They do not show improved grades or knowledge acquisition: no teaching intervention or learning-outcome study was conducted. A study with students would be needed to establish such benefits.

\subsection{Further Validation}
The comparison covers 24 development people from two offerings. Task families and wording were known, and one checkpoint with greedy decoding does not establish performance across models, paraphrases, or deployments. Reserved people remain unevaluated. Human review of answer completeness should precede an evaluation on those independent cases, with the scoring rules fixed in advance.

We have not tested whether users understand the adaptive views better than a fixed dashboard. A user study should compare interpretation accuracy, time to answer, and mistakes about missing values and peer groups. Neither the additional statistical tests nor the duplicate-row check answers that usability question.

\section{\uppercase{Conclusion}}
\label{sec:conclusion}
\noindent The implemented dashboards connect agent selections with deterministic calculations, traceable evidence, and reusable presentation templates. Personal timelines, peer comparisons, observation summaries, and assessment views support different questions through shared analyses. Operators can inspect supporting records and switch among saved comparisons while retaining their analytical context.

Across 24 development cases, explicit analytical identifiers did not improve frozen completeness, while enumeration remained complete and cheaper. The evaluation nevertheless provides concrete guidance for system development. Correctly calculated values can refer to the wrong period or leave a question partly unanswered, while automatically supplied context can complete an answer without model selection. Tracking these contributions separately makes both successful behavior and remaining selection problems visible.

The contribution combines a working tool, interface examples, and reproducible evaluation of answer completeness. Answer equivalence and measurement choices require review before validation on reserved data. Evaluation should examine operator understanding and usability.
