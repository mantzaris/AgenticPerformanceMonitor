# Stage 6 frozen comparison protocol v1

Primary endpoint: complete valid visible answers on each of 24 fresh development
people. Report C–A, C–B and B–A paired both-complete/right-only/left-only/neither
counts. Method-selected completeness is a prominent separate endpoint. No oracle
best-condition mixture, pooled earlier-stage sample, significance or generalization
claim. The fixed engineering gate is at least 22/24 complete visible, zero accepted
unsupported quantitative answers, and both requested personal/peer answers correctly
scoped on all four insufficient-support cases. No completeness feedback enters
the universal validator or model.

Use four people in each existing family: duplicate the two established structural
slots per family with new people. Seed `stage6-structural-v1-20260918`; take minimum
SHA256(seed, case ID, person ID) among structurally eligible unused development
people. Exclude all 57 previous focal people and all 24 new people from the fixed
reference pool across registrations. Do not inspect activity magnitudes or method
performance. Insufficiency slots use recent eligible weeks <2 and at least one
earlier eligible week, retaining explicit separate personal and course-peer requests.
Question wording, feature/window definitions and evaluator predicates are unchanged.

Enumeration executes on the GPU host CPU before agents. Cycle all six permutations
of A/B/C four times across 24 cases: each condition appears eight times in every
position, and each pair runs first twelve times. Reuse one 14B load for comparison.
Shared loading/profile overhead is reported once, not allocated to conditions.
There is one attempt per method/case, up to six analytical calls/four generations/
one final repair. Preserve raw failures, rejections, tool results and stopping
records; no fallback success. Construction is only known Stage 5 06–08, B/C once
each initially, within the separate 32-generation ceiling. Any construction change
must be documented before freeze; no prompt/code/score tuning after freeze.

Freeze people, exclusions, separate row-loop facts, hidden rubrics, code, all
interfaces/prompts, model pin/configuration, source hashes, order and this protocol
before comparison. Evaluator-only facts never enter the compiler, catalogue or
model. A's generic episode and semantic messages remain unchanged. B/C share the
same catalogue; their only difference is selection representation and resolution.

Report validity, complete visible/model-selected answers, requested analyses missing
versus retrieved but not displayed, scoped insufficiency, unsupported attempts,
context attribution, derived metadata, calls/repetitions/generations/tokens/latency.
Mechanism annotations are nonexclusive. Distinguish a rejected malformed binding
from a valid binding to a wrong window/reference for the public request; the latter
is an omission under frozen scoring, not a numerical-integrity rejection. Report
ambiguous/unresolved bindings, scope/support/schema/layout errors and any resource
failure. Oracle evidence sufficiency is offline diagnosis only.

Decision: prefer B over C if equal complete counts and both meet the gate, unless
an explicitly reported adverse integrity/insufficiency result prevents that choice.
C's gain over A without gain over B supports the simpler responsibility split, not
explicit identity. Prespecify a descriptive net gain of at least two cases as a
useful improvement for a missed gate, without interpreting it as statistical
evidence. If neither B nor C meets the gate or improves by two cases over A, recommend
against further tuning on this registry. If an intervention improves but misses
the gate, identify the mechanism and publication blocker without automatically
launching another experiment. Enumeration stays operational unless a demonstrated
benefit justifies change. No model condition can be recommended after an accepted
unsupported quantitative answer.

Inspect first case of each family for all conditions, retaining rejected slots;
supplement with the first valid-incomplete and first rejected case per agent if
absent. Human packet uses those same selections. Replay all accepted outputs and
verify every explicit compiled comparison/change against original selections.
Human scientific/usability review remains pending. If a fixed condition passes,
prepare (only) a final-validation protocol with unopened person-level data,
independent review, locked endpoints/control/order, person-grouped uncertainty and
a bounded compute estimate. Otherwise document why final validation is blocked.

Statistical definitions are unchanged: window peer means give equal weight to
eligible people, with equal weight per observed week within a person; weekly
trajectories use same-week people. Stage 5's closing phrase "equal eligible
person-week weighting" was imprecise documentation; the implemented equal-person
estimator is preserved, not altered here. Bootstrap intervals concern peer means,
not individual predictions or personal/contrast uncertainty. Missingness, source
row duplication, grade timing and reference-family limitations remain as documented.
