# Frozen development pilot protocol v1

Six construction tasks may expose implementation or prompting defects before the pilot freeze. Twelve additional focal people form a small frozen development pilot. No original Stage 1 demonstration counts as new pilot evidence. All 18 are distinct by person, with all registrations grouped by person; the reserved population is unchanged. Task selection uses administrative history and prior-attempt categories, course/profile and a fixed hash, never the direction or size of a result. All tasks use actual records. Synthetic edge fixtures are tests only and are reported separately.

The six question families each occur once in construction and twice in the pilot: personal change, reference sensitivity, observation limits, insufficient support, assessment availability and alternate windows. Full questions, cutoff profiles, selection rules, pool sizes and person IDs are versioned in the task manifest. The evaluator-only rubric contains independently calculated facts, acceptable alternatives (including appropriately qualified insufficiency), required context and prohibited claims. It is **awaiting external human/scientific review**. A separate calculation path is not independent human review.

Methods: (1) a deterministic baseline enumerates the three reference definitions and selects relevant evidence by question-kind rules, adding assessment tools when applicable; (2) a generic tool agent chooses its investigation; (3) a reference-sensitive agent first requests one analysis, then chooses subsequent requests after observing its result, explicitly considering history, reference dependence and limitations. Agents differ only in their policy text. Both use the same pinned model/revision, BF16 Transformers backend, greedy decoding, 1,500 new-token ceiling, tool schema, data, registry, renderer, integrity validator and per-episode budgets (six analytical requests, four generations, one final repair). Context is capped at 16,000 input tokens. All attempted generations count, including errors, repairs and construction. Construction uses six episodes, alternating policies, leaving at least 96 of 120 generations reserved for the 24 pilot agent episodes. No external API or agent-written analysis code is used.

Each method runs once on each frozen pilot task. Agent execution is interleaved by task, generic then reference-sensitive, in manifest order. Fixed greedy decoding does not establish repeatability across environments. The action loop saves every prompt, raw output, parsed request, returned compact result, validation error, stopping decision and token/timing metadata. At most one repair follows a final specification error. An error is never rerun until it passes. No deterministic fallback is counted as agent success; this implementation preserves a separate baseline and leaves failed agent episodes failed.

Integrity versus coverage: universal validation checks source-bound numbers, units, denominators, pointwise intervals, windows/cutoffs, peer exclusions, evidence IDs, visible selected evidence and essential status panels. It does not require a question-specific sequence or reference family. Task scoring independently checks selected analytical coverage and contextual claims against the frozen rubric. Displayed boilerplate supplied by the compiler is reported separately and does not credit the agent with selecting an analysis. The controlled schema cannot emit arbitrary natural-language causal claims; zero unsupported claims in accepted output is therefore a property of this constrained interface, not proof of unrestricted reasoning safety.

Primary report: all 12 tasks remain in each method's denominator. Report first-final-attempt validity, final validity after permitted repair, numerical integrity, per-task coverage and omitted context, unsupported accepted claims, appropriate insufficiency on tasks requiring it, tool counts, attempted generations, prompt/completion tokens, wall latency and GPU-process totals. Failures have zero completed coverage and no accepted numerical-integrity result. The task rubric is not a benchmark score with established validity. Report baseline strengths and any absence of observed agent benefit plainly. No significance test, superiority claim, repeatability estimate, generalization claim or held-out evaluation follows from this pilot.

Freeze `tasks/manifest.json`, evaluator rubrics, registry/configuration, prompts, protocols, source bundle and executable scientific/evaluation code with SHA-256 before **any pilot inference**. Record execution commit and verify the freeze before pilot execution. No tuning after pilot results. Any post-freeze code fix is a protocol deviation, documented with the affected results; do not silently regenerate successful results. Reports and verification logs may be added without changing frozen pilot inputs.

Resource accounting: an append-only stage execution ledger records scope and CPU milestones. A separate locked append-only model ledger is canonical for cumulative model starts, finishes and attempted generations across restarts. Startup/imports/load/rendering within a model process count toward its runtime, separate from stage elapsed time. An unclosed process reservation blocks automatic restart until reconciled. Completed processes are stopped; RunPod billing time is not inferred from CUDA event time or process runtime.
